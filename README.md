# 中南大学 H5 安全待确认辅助工具

> 一个在本机运行的小工具：把学校 H5 的「班级打卡看板」搬到电脑上，变成一个可核对、可批量提交、提交后自动回读校验的操作面板。**默认只读，账号密码与最终提交都由人把关。**

## 它解决什么问题

晚寝打卡的「安全代确认」是班长每天最耗时间的环节：在手机 H5 上逐人点开核对、逐人填核实方式和情况说明、提交完还要一张张翻回去确认状态。手工做有两个风险——漏人、填错。

这个工具把三步搬到电脑上：

| 原来 | 现在 |
| --- | --- |
| 手机小屏逐人翻看 | 面板表格列出全班待确认名单，可逐行改核实方式与说明 |
| 逐人点开表单填写 | 一次操作按统一字段批量填写，逐条回读校验后才继续 |
| 提交后手工回看 | 自动重读看板，只有全员显示「已代确认」才判定完成 |

## 设计原则（也是安全边界）

- **不碰凭证**：账号、密码、验证码、Cookie 全部由学校统一身份认证页面和浏览器自己处理，工具只读页面可见内容。
- **不调未公开接口**：只操作浏览器里真实渲染的官方表单，不走后台 API。
- **默认只读**：打开页面、读名单、比对快照都是只读的；任何写操作都必须由人勾选确认后逐条点击。
- **人工关口不可代劳**：逐人核实勾选、监督勾选、最终提交按钮，工具不会替你点。
- **异常即停**：结果不明、部分成功、页面结构变化、名单变动，一律立即停止且当日不再重试。
- **最小留痕**：只保存日期、人数、状态和 HMAC 摘要，不落盘姓名、学号、页面原文。

## 项目结构

```
app.py                 本机面板服务：HTTP 端点、批次编排、每日防重、只读计划任务
browser_bridge.py      通过本机 CDP 连接独立 Edge：移动端模拟、页面读取、标签清理
official_adapter.py    官方看板与代确认表单的 DOM 适配器（纯 Playwright，不碰网络接口）
roster_parser.py       看板文本的严格解析与一致性校验
panel.js               面板交互：登录门面、名单核验、分步/一键批次、实时名单
tests/                 120+ 项测试，全部使用假浏览器与脱敏样本
start.cmd / start.ps1  启动面板
setup.ps1              首次安装依赖
install-task.ps1       安装每日只读检查的计划任务
```

## 工作原理

1. **独立 Edge**：工具启动一个专用配置（`data/edge-school-direct-mobile`），通过 `--remote-debugging-port` 暴露本机 CDP，不接管你日常的 Edge 窗口。移动 UA 以 `--user-agent` 进程参数注入，面板重启也不会丢。
2. **移动端模拟**：CDP 会话设置视口、触摸和 UA；学校站点的「请使用手机打开」门禁因此可以正常通过。
3. **读看板**：`official_adapter` 按官方 DOM 结构（卡片、状态 chip、筛选标签）解析名单，并交叉校验汇总人数；严格解析器与卡片阅读器互为兜底。
4. **逐条提交**：每条提交前重读看板与核验快照比对，提交后回读「全部」视图，确认目标变「已代确认」、待确认数恰好减 1、他人不变，才继续下一条。
5. **终检**：整批结束后再完整读一次看板，全员「已代确认」才判定完成，面板同步刷新全班实时状态。

## 快速试用（不需要学校账号）

登录门面下方有「进入本地演示」链接，可以跑通名单、核验、预览、批次校验等全部流程——只是提交用的是本地假数据，不会碰学校。适合先看看交互是否符合你的习惯。

## 启动

需要 Windows、Python 3.11 或更新版本，以及已安装的 Microsoft Edge。首次运行：

```powershell
cd <克隆下来的项目目录>
.\setup.ps1
```

安装脚本会创建 `.venv` 并安装页面连接依赖；不下载额外浏览器。之后双击 `start.cmd`，或运行：

```powershell
.\start.ps1
```

面板地址是 [http://127.0.0.1:8767/](http://127.0.0.1:8767/)，服务只监听本机回环地址。关闭控制台窗口即停止。

## 连接学校 H5

1. 点击“打开校园 H5 登录”。工具会启动独立的 Edge 配置 `data\edge-school-direct-mobile`，不会接管已有的普通 Edge 窗口。
2. 在该窗口中按学校流程正常登录，不要把账号、密码或验证码发给工具。
3. 官方业务入口是“平安打卡 → 班长入口 → 班级打卡看板 → 安全代确认”。登录成功后工具会**自动导航到学校官方 `#/ywViews/qxjlfx/dqr/board` 看板并读取今日待确认名单**，无需再点按钮；名单已加载或批次正在执行时不会重复触发。“刷新学校页面”“打开待确认名单”按钮保留用于手动刷新。当前只允许当天名单；历史日期、未来日期和无法确认日期的页面不会打开或核验。

日期必须是有效的 `YYYY-MM-DD`，非当天日期会在导航前拒绝。浏览器连接失败、登录过期、页面要求手机环境或页面结构未识别时，面板会停在对应状态，不会继续提交。

面板打开后首先显示登录门面：点击“打开校园 H5 登录”会在独立 Edge 窗口打开学校官方页面，登录由学校统一身份认证页面完成，工具不读取、不保存账号、密码、验证码或 Cookie；门面每约 3 秒检查一次学校页面状态，登录成功后自动进入工具并读取代确认名单。若暂时不连接学校，也可通过门面下方链接进入本地演示区域，但学校提交仍需真实看板连接。

## 全班打卡状态（实时核验）

“全班打卡状态”区域读取官方看板“全部”视图，列出每位学生当前的实时状态（未打卡 / 已打卡 / 已代确认）与汇总人数；可随时手动刷新，批次提交完成后也会自动刷新。批次结束时工具会再做一次终检：只有完整名单里每一位提交对象都显示“已代确认”，才算本批完成——这也是“务必看到名单全部写着已代确认”的机器保证。该区域只做只读展示，不提交任何记录；批次执行期间端点会暂停响应，避免与提交争用页面。

## 本地核验与计划任务

学校看板区域支持整体核验和当天快照：你确认完整名单后，工具只保存日期、时间、人数、来源和 HMAC 摘要，不保存姓名、学号或页面原文。默认每天 `09:00`（`Asia/Shanghai`）重新打开当天官方看板并核对可见的“未打卡”筛选状态，再与学校核验快照比较；名单、日期、路由、筛选状态或登录态异常时暂停，错过时间不补跑。Windows 计划任务可用以下命令安装或修改：

```powershell
.\install-task.ps1
.\install-task.ps1 -At '08:30'
```

计划任务只做官方学校看板的只读比较，不提交学校业务记录。每日自动提交未启用；批次必须由你在面板上检查并点击提交。

## 一键提交已核实批次

### 一键代确认快捷入口（默认“电话 / 已确认”）

在“学校 H5”区域读取今天完整名单并逐人核实后，勾选“我已逐人核实以上完整名单中的每个人安全，且确实无法本人打卡”，点击一次“一键代确认并立即提交”：工具自动保存今日名单核验快照，把上方统一字段（默认核实方式“电话”、情况说明“已确认”，可在点击前修改）应用到每一人，生成完整批次预览，并立即向学校官方页面逐条提交。**点击后无二次确认**；每个日期最多尝试一次，一旦开始当天无法再次提交；结果不明或部分成功立即停止，须人工核对官方记录，不会自动重试。只有本批每个人确实均通过电话核实、且情况说明一致为“已确认”时才能使用；有人方式不同或说明不同时，请改用下方分步流程逐人修改后提交。逐人核实勾选是人工关口，工具不会代替勾选。

### 分步流程

1. 在“学校 H5”区域读取今天完整名单，逐人核实实际情况，再勾选完整名单核验并保存快照。
2. 检查每行核实方式和情况说明。三种官方方式为“电话”“当面”“室友转达”，说明必填且最多 100 字。统一字段只适用于事实确实相同的批次；字段编辑后已有预览失效。
3. 点击“生成完整批次预览”，检查日期、人数、每人姓名、学号、核实方式和说明。预览五分钟有效，必须恰好覆盖当前完整待确认名单。
4. 勾选已检查整个批次且会监督这次真实提交，再点击“一键提交全部”。保持电脑开机、网络连通，并保留独立 Edge 和面板。
5. 工具按官方页面逐条填写提交。每条提交后刷新“全部”看板，只有目标变为“已代确认”、待确认人数恰好减少 1 且其他记录不变，才继续下一条。面板显示已验证成功数量和最终结果；结果不明或部分成功立即停止，不会重试或接着提交。
6. 批次结束后工具会再完整读取一次“全部”看板做终检：只有每一位提交对象都显示“已代确认”才判定整批完成，否则降级为结果不明并停止。“全班打卡状态（实时核验）”区域随后自动刷新，可直接看到整个名单的实时状态。

提交前会重新读取官方名单并与预览、当天核验快照比较。日期、名单、状态、来源、登录态或页面结构变化均暂停；必须重新读取并整体核验。提交通过 `/api/prepare-batch` 和 `/api/batch-submit` 完成；旧 `/api/submit` 仍返回 `403`，不能绕过预览和监督步骤。

每个日期最多尝试一个批次。`data/batch-attempt-YYYY-MM-DD.done` 在连接提交浏览器之前写入，进程中断、浏览器报错或重启也不会自动再次提交。出现异常请人工核对学校记录，不要删除标记来强制重试。最新结果保存在 `data/batch-result.json`，只含时间、状态、数量和固定说明（含终检确认人数，不含姓名学号）。

代码测试使用脱敏样本和假浏览器，只能证明程序保护流程，不能证明当前学校页面的真实提交已成功。第一次真实提交前，建议先用一条确实已核实的记录走一遍分步流程，确认交互和后端行为符合预期。
